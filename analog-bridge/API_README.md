# Analog Bridge SCPI Interface

The analog bridge is an ATtiny3226-based 16-channel data acquisition device.
It reads four ADS1115 converters and exposes one line-oriented SCPI interface
over Ethernet and over the USB serial adapter. There is no HTTP or JSON API.

## Hardware

Four ADS1115 devices share the I2C bus. Each contributes four single-ended
inputs:

| Logical channels | ADS1115 address | Inputs |
| --- | --- | --- |
| 0-3 | `0x48` | AIN0-AIN3 |
| 4-7 | `0x49` | AIN0-AIN3 |
| 8-11 | `0x4A` | AIN0-AIN3 |
| 12-15 | `0x4B` | AIN0-AIN3 |

The ATtiny3226 wiring is:

| Function | Pin |
| --- | --- |
| I2C SCL | PB0 |
| I2C SDA | PB1 |
| UART TX | PB2 |
| UART RX | PB3 |
| ADS alert 0-3 | PB4, PB5, PC0, PC1 |
| ENC28J60 MOSI/MISO/SCK | PA1, PA2, PA3 |
| ENC28J60 CS/INT | PA4, PA6 |
| UPDI | PA0 |

## Transports

### Ethernet

The ENC28J60 obtains an address with DHCP and listens for SCPI connections on
TCP port `5025`. The startup message contains the address:

```text
SCPI ready: tcp://192.168.1.42
```

Connect with any TCP client, send one command per line, and read the response
line or lines. For example:

```bash
printf '*IDN?\n' | nc 192.168.1.42 5025
printf 'MEAS:RAW? 6\n' | nc 192.168.1.42 5025
```

The MAC address is locally administered and generated by hashing all ten bytes
of the ATtiny factory serial number. Each device therefore gets a stable MAC
without exposing the factory serial directly.

### USB serial

The ATtiny3226 firmware uses its UART; connect PB2/PB3 to a USB-UART adapter
or a board USB-UART bridge. Use `115200 8N1`, with TX/RX crossed and a shared
ground:

| ATtiny3226 | USB-UART adapter |
| --- | --- |
| PB2 / TX | RXD |
| PB3 / RX | TXD |
| GND | GND |

Send SCPI commands terminated by LF or CR/LF. Startup diagnostics are also
printed on this port, so software should ignore lines before the first command
response.

## SCPI commands

Commands are case-insensitive. Whitespace around a command is ignored. The
device processes one command per line. Query commands end in `?`; setter
commands return `OK` or the effective value.

| Command | Response / effect |
| --- | --- |
| `*IDN?` | `AnalogBridge,16-Channel Analog Bridge,ATtiny3226,1.0` |
| `*RST` | Enables all channels and restores 16 SPS; returns `OK` |
| `SYST:ERR?` | Returns `0,"No error"` or the latest error, then clears it |
| `CONF:CHAN<n>:RATE <sps>` | Sets channel `n`; returns effective rate |
| `CONF:CHAN<n>:RATE?` | Returns effective rate in SPS |
| `CONF:CHAN<n>:STAT ON` | Enables channel `n`; returns `OK` |
| `CONF:CHAN<n>:STAT OFF` | Disables channel `n`; returns `OK` |
| `CONF:CHAN<n>:STAT?` | Returns `ON` or `OFF` |
| `MEAS:RAW? <n>` | Returns the latest signed ADC code, or `NAN` before its first sample |
| `MEAS:RAW:ALL?` | Returns 16 CSV lines: `channel,enabled,rate,value,timestamp` |

`<n>` is an integer from `0` through `15`. Supported ADS1115 rates are `8`,
`16`, `32`, `64`, `128`, `250`, `475`, and `860` SPS. A requested rate is
rounded down to the greatest supported rate; values below 8 select 8 and
values above 860 select 860.

Examples:

```text
*IDN?
AnalogBridge,16-Channel Analog Bridge,ATtiny3226,1.0
CONF:CHAN6:RATE 128
128
CONF:CHAN6:STAT OFF
OK
MEAS:RAW? 6
1234
MEAS:RAW:ALL?
0,1,16,123,5812
1,1,16,NAN,NAN
...
```

Invalid commands return `ERROR`; query `SYST:ERR?` immediately afterward for
the diagnostic. The interface has no authentication or encryption, so use it
only on a trusted network.

## Measurement behavior

Values are raw signed 16-bit ADS1115 conversion results. The firmware uses
`GAIN_ONE`, whose nominal input range is approximately +/-4.096 V. Convert to
volts in host software if required, while respecting the ADS1115 electrical
limits.

The timestamp is `millis()` since boot, not Unix time. It is returned as the
fifth CSV field and is `NAN` until that channel has a valid sample. Each
ADS1115 converts one input at a time, while the four devices can convert in
parallel. The configured rate is a per-channel scheduling target; use
timestamps to measure the achieved rate. Configuration is held in RAM and
resets to all channels enabled at 16 SPS after power loss or reset.

## Minimal Python client

```python
import socket

def scpi(command, host="192.168.1.42", port=5025):
    with socket.create_connection((host, port), timeout=2) as sock:
        sock.sendall((command + "\n").encode("ascii"))
        return sock.recv(4096).decode("ascii").strip()

print(scpi("*IDN?"))
print(scpi("CONF:CHAN6:RATE 128"))
print(scpi("MEAS:RAW? 6"))
```

For continuous acquisition, keep one TCP connection open and send queries
periodically. The firmware does not emit unsolicited measurement data.

## Two-device Python monitor

`analog_bridge_monitor.py` searches the local IPv4 `/24` networks for up to two
Ethernet bridges on TCP port `5025`. It also probes USB-UART ports when
`pyserial` is installed. After discovery it continuously queries every channel
and serves a live 32-square dashboard when two devices are found:

```bash
python3 -m pip install pyserial
python3 analog_bridge_monitor.py
```

Open `http://127.0.0.1:8080`. Each square shows the device, channel, transport,
IP address or serial path, measured voltage, and the ADS timestamp. The default
3.3 V logic classification is:

For a USB-UART bridge such as `/dev/ttyUSB0`, the port can be selected
explicitly:

```bash
python3 analog_bridge_monitor.py --serial-port /dev/ttyUSB0
```

| Voltage | Display |
| --- | --- |
| `>= 2.00 V` | `HIGH` |
| `<= 0.80 V` | `LOW` |
| Between the thresholds | `doubt` in red |

Override the thresholds or web port when needed:

```bash
python3 analog_bridge_monitor.py --high 2.2 --low 0.7 --port 8080
```

The scan relies on TCP port access and validates the `*IDN?` response rather
than using broadcast. The firmware accepts one active TCP client at a time.
If the devices are on a different subnet, add that subnet to the script's
`local_networks()` function or replace discovery with known addresses.

## Direct ADC test firmware

To bypass the SCPI scheduler and test the ADS1115 hardware directly, build and
upload the `ADC_TEST` environment:

```bash
pio run -e ADC_TEST -t upload
```

`Upload_UPDI` is the default PlatformIO environment, so the PlatformIO Upload
button uploads the normal SCPI firmware. Select `ADC_TEST` only when you want
to upload the diagnostic firmware again.

Open the USB serial port at `115200 8N1`. It prints one line per input every
second:

```text
read,0x48,0,12345
read,0x48,1,12346
read,0x49,0,23456
```

The fields are `read,<ADS1115 I2C address>,<AIN channel>,<raw signed value>`.
It also prints `probe,0x48,present` or `probe,0x48,missing` at startup. A 3.3 V
input should be approximately `26000` raw counts with `GAIN_ONE`; a persistent
`0` or `ADS_MISSING` identifies an I2C, power, address, or wiring problem
independent of the normal application.

## Network oscilloscope example

`analog_bridge_oscilloscope.py` discovers up to four bridges on the local
private `/24` networks and plots AIN0 from every ADS1115 on one shared canvas.
The plotted logical channels are `0`, `4`, `8`, and `12`, corresponding to
AIN0 at addresses `0x48`, `0x49`, `0x4A`, and `0x4B`. Each device/channel can
be activated independently. It uses the `timestamp` field from
`MEAS:RAW:ALL?`, normalizes each device to its first observed timestamp, and
displays the selected traces over a shared elapsed-time axis:

```bash
python3 analog_bridge_oscilloscope.py
```

Open `http://127.0.0.1:8090`. Adjust the rolling time window and polling rate
with command-line options:

```bash
python3 analog_bridge_oscilloscope.py --history 60 --poll 0.1 --port 8090
```

The four devices do not share a hardware clock, so synchronization is relative
to each device's first observed `millis()` timestamp. The original device
timestamps remain available in the `/api/state` data returned by the example.
